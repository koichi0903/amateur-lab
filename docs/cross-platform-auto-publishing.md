# Cross-platform automatic publishing

## Decision

Build one publishing queue for YouTube Shorts, Instagram Reels, and Threads. Add it to the existing admin social-growth workspace instead of creating another top-level admin page. Preserve the current X workflow and connect each destination only after its own OAuth authorization and platform publishing requirements are met. TikTok has been fully retired from this project’s publishing workflow, including manual clip preparation.

## What automation means

- The publishing team prepares media, platform-specific copy, and a scheduled time.
- The user reviews each exact post revision for YouTube Shorts, Instagram Reels, or Threads before it enters the server-side scheduled queue; after approval, the queue publishes at the scheduled time without further per-post work. There is no TikTok route.
- A failed token or provider request stops that job and reports the error; ambiguous outcomes are not retried automatically.
- A unique idempotency key prevents duplicate queue entries. A daily publishing cap is still not implemented.
- Every published item records provider post ID, timestamp, and approved content revision.

## Required components

1. Admin channel connections for YouTube and Meta (Instagram and Threads).
2. Server-only OAuth callbacks and encrypted refresh/access-token storage.
3. A publish queue with `draft`, `awaiting_user_review`, `scheduled`, `publishing`, `published`, `failed`, `paused`, and `rejected` states. Only an explicitly reviewed content revision may enter `scheduled`.
4. A scheduled worker that claims due jobs safely and calls only official publishing APIs.
5. A cross-platform asset pipeline that stores a distinct media file per platform and retains source provenance.
6. Per-platform publishing adapters, result logging, retry policy, and a kill switch.

## Platform prerequisites

- YouTube: Google OAuth client and channel-owner consent; Data API upload scope and upload quota. Sample-derived Shorts are limited to vertical or square output, and this pipeline clips to at most 60 seconds. In this queue, `scheduled_at` is the upload/dispatch time: `public` is public after the upload is processed, `unlisted` is link-accessible, and `private` stays private. This is not YouTube's native future `status.publishAt` schedule. As of the YouTube Data API revision published 2026-11-02, uploads from unverified API projects are no longer automatically restricted to private visibility; the queue still sets and shows the exact user-selected privacy status. A compliance audit is relevant to requests for quota beyond the default allocation, not as a prerequisite to choose public visibility.
- Instagram Reels: Meta app and authorized Instagram professional account; public media URL and content-publishing permission.
- Threads: Meta app and account authorization for content publishing.

## Release gates

- Do not place API secrets in browser code or committed files.
- Keep queue and OAuth tokens server-only; use RLS and least privilege.
- Do not publish during local verification or a Preview/Production investigation.
- Auto-publishing remains off until the account owner completes that destination's OAuth grant and enables its channel once. The user must still approve every exact post revision before it can enter the scheduled queue; standing channel authorization does not replace this per-post review.
- Channel activation requires confirmed publishing scopes. A requested scope is never stored as granted when a provider omits the granted-scope field. Threads scopes are read from Meta's official Threads token debugger during OAuth; the user token is checked against the app ID and only the debugger's returned scopes are stored. Instagram’s applicable login mode verifies the exact `@hakkutsu_lab` professional account with the minimum granted publishing scopes. Immediately before publishing, stored scopes are checked again; a channel with missing required scopes is disabled and the job is stopped. TikTok is outside the supported platform allowlist.
- Each post must be shown with a playable/viewable private-media preview, exact caption, destination, and scheduled time. The user must explicitly approve that exact content revision before it can be scheduled; edits invalidate the approval and return it to review. Rejected or pending items never enter the publishing worker.
- The worker must select only rows with `status = 'scheduled'`, `review_status = 'approved'`, and `approved_revision = content_revision`, then re-read and validate the same values immediately before the provider API call. Content edits increment the revision and invalidate approval; rejected/published/failed job content is immutable and a replacement requires a new job.
- Assets must pass the relevant source-use and destination requirements. Trimming alone does not establish permission or suitability, and account-owner review does not override platform policies. Do not conceal a commercial/adult destination or use media that the destination prohibits. The admin can select a work with a stored official HTTPS FANZA/DMM sample video, preview it, request a clip of up to 60 seconds, and save the transcoded MP4 to private storage. The queue records the work ID, sample host and URL hash, trim interval, and media checksum. This technical path does not establish that a particular clip is non-sensitive or suitable; the exact private clip, caption, destination, and time remain user-review-gated.
- Production release requires one finished implementation and a single approved deployment.
